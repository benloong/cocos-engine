# M6 Native 更新期间再次标脏

本节点接续 d6ceddb1b0 的移除安全修复。旧版本在本轮结束前一直保留 renderer 的排队版本，因此自身回调或后续 renderer 对它再次标脏会被去重，最后整体清空队列，漏掉新工作。仅调整队列还不足以修复：更新末尾 clearRenderDirty 也可能覆盖回调刚设置的新脏标记。

## 调度约定

- 本轮尚未更新的对象保持当前队列合并规则，新加入对象仍可本轮处理。
- 本轮已更新或正在更新的对象再次标脏，合并到下一轮队列；同一对象每轮至多执行一次。
- 新旧排队版本分别对应当前队列和下一轮队列，禁用、解绑或销毁会从对应队列取消条目。
- 当前对象回调新产生的脏标记单独保存，更新末尾清理旧状态时保留，下一轮再消费。
- 保留 Native 组件独占所有权；回调返回后 manager 不解引用该对象。Web 实现不变。

## 验证

Windows Debug／Release 原生完整回归及 JSB manager 探针通过。新增回归覆盖自身再次标脏与尾部清理、后续对象修改已更新对象、重复标记合并、更新中禁用再启用，以及销毁取消已排入下一轮的工作。既有移除、重入刷新和当前轮追加用例继续通过。

双配置各 146 张核心捕获与既有 Native 基准逐字节一致，22 项命中、11 项根节点、1000 轮场景及 4998 项场景断言通过。基线检查与 43 项薄壳检查通过。原始记录见 [图像验证](../native/tests/2d-poc/build/m6-deferred-dirty-node/pixel-validation.json)，同目录含 native-results.json、graphics-results.json 和构建日志。

本节点未重新测量性能或运行 ASan。字体文件独占失败及 M6 其他终态签收项继续保留，不据此认定 M6 完成。
