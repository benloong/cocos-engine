# Windows 和 Web 的 M6 性能对照

## Label 诊断清理后的 Windows 复测

Windows x64 Release 同机依次运行迁移前版本 M（7e83734299）、清理前版本 P（8fe41d68af）和清理后版本 C（290d535223）。六轮顺序依次为 MPC、PCM、CMP、CPM、MCP、PMC。每种场景预热 30 帧，随后记录 120 个静止帧和 120 个变更帧。CPU 包含 setter、脏组件更新和合批。表中单位为 ms/帧，三列版本数据取各轮帧中位数的中位数，末列先逐轮相减再取中位数。[六轮逐项数据](./native-2d-m6-label-coverage-performance.json)

| 场景 | 迁移前 | 清理前 | 清理后 | 同轮清理后减清理前 |
|---|---:|---:|---:|---:|
| 1000 个 Sprite 静止 | 0.2048 | 0.3119 | 0.2889 | -0.0070 |
| 100 个 Sprite 改色 | 0.3177 | 0.4360 | 0.4498 | -0.0010 |
| 20 个 Label 改文本 | 3.0952 | 2.1014 | 2.1768 | 0.0564 |
| 4 个 RichText 改文本 | 1.8663 | 1.0730 | 1.1113 | 0.0216 |
| 混合静止 | 1.1087 | 1.1470 | 1.1857 | 0.0246 |
| 混合变更 10% | 4.7116 | 3.5903 | 3.4639 | -0.1113 |

混合变更帧从迁移前的 4.7116 降至 3.4639 ms，下降 26.5%。50% 门槛为 2.3558 ms，尚差 1.1081 ms/帧。

只比较清理前后，混合变更帧六轮均变快，配对差的中位数为 −0.1113 ms。纯 Label 四轮变慢、两轮变快，RichText 各三轮；这组端到端数据不能把清理收益直接折算成单次文字重绘耗时。混合变更帧相对迁移前，setter 从 1.5482 降至 0.4480 ms，脏组件更新从 2.0928 降至 2.0372 ms，合批从 0.8750 降至 0.8639 ms。当前耗时最大的一段是脏组件更新。各段独立取中位数，其和可与整帧中位数不同。

纯 Sprite 没有经过 Label 清理路径。相对迁移前，静止帧合批从 0.2026 升至 0.2837 ms。改色帧的 setter、脏组件更新、合批从 0.1250、0.0020、0.1834 ms 升至 0.1743、0.0177、0.2335 ms。

混合变更帧的 JSB 为 876 → 197 次/帧，JS 堆峰值为 30,048,820 → 17,041,052 字节，强制 GC 为 8.5000 → 6.2855 ms。每轮每场景每个阶段只执行一次强制 GC。

复现使用 native/tests/2d-poc 下的 prepare-m6-perf.cjs 与 run-m6-perf.ps1。迁移后的两个版本均从独立检出构建，使用 --isolated-project 及 -ProjectRevision，运行 Windows 时开启 -TextWidthProbe。六轮的九组系统字体测量值和 RGBA 哈希在清理前后全部一致。Web 完成同版本的 12 组负载，Windows KPI 使用同轮 Windows 结果。

## Windows Canvas 矩形填充

栅格 Label 在新画布上用边缘色和 1/255 的透明度填充整块纹理。目标像素完全透明且矩形完整覆盖时，source-over 的 straight RGBA 等于源 RGBA；不透明源完整覆盖目标时同样成立。Win32 Canvas 在这两种情况下直接复制四个通道。其他情况沿用原先的覆盖率计算，包括小数边缘和半透明颜色叠加。

在同一台 Windows 主机上，用 MSVC Release 编译前后两份填充函数。65,536 个固定种子的输入覆盖混合目标 alpha、正负矩形尺寸、裁剪、小数坐标和源透明度，输出全部逐字节一致。256 次 96×24 透明背景填充的中位数从 9.175 ms 降至 0.685 ms，含每次清零。另行比较位图读回实现时，256 次创建、绘字和读取在 GetDIBits 与 DIB section 两条路径上分别为 5.384、5.391 ms，因此本次保留原位图路径。

Windows Debug/Release 的 native harness 均通过；1000 次 Canvas 生命周期循环前后的进程 GDI 句柄均为 16。三端 85 张常规图像逐字节一致。当前快照的 12 个 RichText 场景在两个 Windows 配置上与 Web 的布局均一致，各自图像哈希与上一节点相同，严格通过 9/12。

Windows Release 迁移前、换行修正对照和本次候选采用相同的三轮交错测量。已迁移的两个程序复用相同 Label 对象文件、JS 包和计时工程，候选替换 Win32 Canvas 翻译单元。混合负载三轮均优于改动前；纯 Label 的首轮回退，三轮中位数仅改善 0.5%。9 张系统字体纹理在各轮优化前后与前一节点逐字节一致。[逐轮数据、图像及构建哈希](./native-2d-m6-canvas-fill-performance.json)

| 混合负载，总 CPU（ms） | 4.3008 | 4.8806 | 4.1284 |
| 混合负载，dirty 更新（ms） | 1.9610 | 3.3985 | 2.7890 |

混合 CPU 较改动前下降 15.4%，较迁移前下降 4.0%，距 50% 目标仍差 1.9780 ms/帧。每轮的具体对照受进程间波动影响，不能将本次百分比与上一节点的百分比累加。

| 在带探针的同一帧内扣除 append 后的余量 | 0.1294 | 0.1274 |

两种负载都调用 append 1000 次/帧，将 144000 字节顶点数据写入页，重排 6000 个索引。另做四对交替启动的局部计时，旧版测 fillIndexBuffers 整体及其中的索引 memcpy，新版测 append 整体及其中从 vertices.insert 到索引重排结束的区间。扣除旧路径后，两端完整函数的净差为静止 +0.0877、改色 +0.0879 ms/帧。仅比较写入区间的净差为 +0.0865 和 +0.0893 ms/帧，分别相当于上述 update 差距的约 66% 和 85%。余下约 0.0442 和 0.0159 ms/帧尚未细分。

每 53 次调用分别抽 1 次测整函数、1 次测写入区间、1 次测连续读钟，扣除空读钟耗时后按实际调用数折算。主测试中，局部探针使当前 update 均值增加 0.0337 和 0.0189 ms/帧。独立抽样的写入区间估计有时高于整个函数，说明计时边界对短函数的估值有影响。占比只用于定位开销，不能作为省去页复制后的预计提速。[各轮采样、计时口径与二进制哈希](./native-2d-m6-sprite-page-profile.json)
