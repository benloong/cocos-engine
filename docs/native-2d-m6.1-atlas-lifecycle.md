# M6.1 动态图集帧所有权与重置

动态图集管理器持有页面，页面记录使用每份源纹理上传的帧。删除单帧、销毁帧、主动恢复或替换纹理时移除对应记录。仍有源纹理使用者时保留上传记录，页面没有上传记录时从管理器移除后销毁。

已打包的 SpriteFrame 克隆登记到原页，同时保留独立的原图与几何恢复状态。删除源纹理时恢复该源的使用者，页面重置先解除登记，再恢复帧和释放页面纹理。重置期间拒绝同步回调触发的打包。Frame 到页面的索引使用 WeakMap，定位所属页面，不引入原生 shared_ptr；SpriteFrame JSB 继续直接操作自身的原生绑定。

Web Jest 覆盖共享纹理、克隆、手动删除、销毁、场景启动事件、源纹理删除及主动恢复。真实 Windows Debug 和 Web 的 M4 夹具要求 M6_ATLAS_LIFECYCLE_PASS，验证相同的共享帧及克隆删除顺序、重置恢复和源纹理删除。两个入口都保留原有像素断言，构建与测试按[统一流程](./native-2d-build-and-acceptance.zh-CN.md)执行。

真实 Web 初测暴露发布打包器把 Map/Set 展开转成数组拼接，Jest 环境没有重现。帧快照改用显式 Array.from，覆盖两种构建路径。

最终候选完成双端 CLI 构建、NATIVE override、资源同步、Windows Debug 编译和完整串行验收。M0、独立 M2–M5、SpriteFrame UV 和定向 Jest（7 个 suite、37 项）全部通过。100 份实际 GPU 图像逐字节一致。M5 用时 40.07 秒，预算 45 秒。

完整实际场景切换、native C++ 直接改写帧的跨语言所有权、自动合图和跨平台仍列入 M6。
