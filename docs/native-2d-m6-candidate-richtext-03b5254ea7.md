## 早期失败与诊断

本轮最初 Debug、随后串行 Release 均被启动器判为提前退出，最后截图在模板禁用阶段，原启动器未能读出原生退出码。这两次继续记为失败，不能因最终复跑通过而撤销。补充缓存 Process.Handle，使 Windows PowerShell 可以保留 ExitCode；独立退出控制返回预期值 37。此改动补齐诊断，不足以证明前两次失败的原生原因已消除。

诊断启动器运行越过模板重建与销毁阶段，没有捕获第二次异常；该次没有字体检查点服务，最终诊断超时，不算正常应用通过。并行启动的 Release 曾因诊断进程占用共享字体而在独占读取预检失败，已与引擎回归分开记录。

从当前 Native 源码重建的 ASan 应用通过了模板重建阶段，运行到约第 401 个字体循环时达到原有 180 秒预算，未报告 sanitizer 内存错误。线程采样位于正常 Engine.tick 帧循环。ASan 本轮仍为超时失败，不据此声称无泄漏或通过完整稳定性门禁。正常 Debug／Release 的 180 秒预算保持不变。
