# M6.1 动态图集回退与页面容量

打包入口拒绝压缩纹理、非 Texture2D、无来源 ImageAsset、空尺寸、超出 maxFrameSize 或页面尺寸的纹理，以及现有不兼容的采样配置。手动设置 packable 仍需通过这些检查。失败时继续使用原图和原 UV。

页内先计算候选位置。新区域能放入时才推进游标，避免一个较大的纹理失败后占掉较小纹理仍可使用的空间。管理器用实际页数限制新建页，优先复用已上传的同一纹理，再搜索已有页剩余空间。重置恢复追踪的帧并清空计数，测试覆盖一页达到上限后复用共享纹理及恢复原图。页由管理器持有，Atlas 管理自己的动态纹理及帧记录。

定向 Jest 覆盖压缩标志、GPU-only 纹理、RenderTexture、超大来源、满页和较小纹理继续分配。Windows Debug 与 Web 的真实 M4 夹具检查无来源图像及过大来源保留原图、同一页复用、重置恢复，并保留原有 RGBA 对照。构建与验收入口见 [统一流程](./native-2d-build-and-acceptance.zh-CN.md)。

最终候选按文档完成双端 CLI、NATIVE override、资源同步与 Windows Debug 编译，M0、独立 M2–M5、SpriteFrame UV 和定向 Jest（7 个 suite、36 项）全部通过。100 份图像逐字节一致，包括 12 份 Sprite/Mask、12 份字体合图和 76 份字体布局。M5 完成用时 40.88 秒，预算 45 秒。

自动触发、手动删除和跨场景资源完全释放、图片上传失败回退、实际压缩解码器及跨平台仍由 M6 后续项验证。排布继续由 Web/native 共用的动态图集管理器负责。
